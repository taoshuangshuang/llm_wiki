# 长文子块串行入库与分批审阅实施记录

- 日期：2026-10-29。
- 对应设计：[长文子块串行入库与分批审阅设计](长文子块串行入库与分批审阅设计.md)。
- 交付范围：本地源代码、相关回归和真实本地服务评估。没有安装或替换桌面发行包，没有自动重跑历史失败任务。

## 已实现的行为

来源超出预算或普通分析输出截断后，先保存固定子块计划，再逐块分析、生成、写入和审阅。块内截断只细分该块的分析输入，不增加逻辑任务。主体、重叠内容与前序摘要分别传入；覆盖校验以主体快照为准。分段仍沿用标题、段落、句子及字符兜底规则，记录规范化正文中的 UTF-16 分段范围。

`.llm-wiki/ingest-documents/<documentRunId>/` 保存来源版本、切分计划、预留运行身份及完整分析断点；子块复用 `ingest-runs/<runId>/` 的可靠写入记录。相同正文的不同子块不会合并，父计划落盘后的中断可按预留身份幂等恢复。分析断点同时校验输入规则和输出正文指纹，生成断点包含运行身份。旧整文分析断点不转成新子块计划。

自动入库、来源监控、交互分析、交互确认后的写入、对话材料入队及手动审阅共用应用级串行入口。交互流程等待用户确认期间释放执行名额。写入队列固定一个工作者，保留旧设置接口但不再放大并发。队列记录固定来源运行 ID，重复导入同一路径时，不把历史记录误认作当前任务。

每个子块在本轮审阅结束后才推进下一块。审阅某批失败后继续尝试后续批；当前块写入不完整时保留成果并停止本来源后续块，允许队列继续其他来源。暂停、取消、项目切换与仅审阅重试保留持久进度；取消后的迟到模型响应不能提交当前事项。

知识页路径按二进制顺序去重排序，每 10 页一批，导航和日志页不占名额。批次身份绑定成员和版本。每批检索请求共用 60 秒、320 候选、32 查询和 40,000 正文字符预算；重试保留有效成功目标，未执行目标继续执行。Rust 保存通道候选检查点，验证通道配置、查询、语料和候选版本后复用成功通道，再由原 RRF 核心重新融合。

每批模型请求上限为 16 次；来源覆盖和本轮关系检查按有限检查段分别计量。检查点保存模型结果、材料路径、版本与范围、累计调用统计和真实错误。正文放不下时分段；单行或关联证据对仍无法放入时明确记录未完成。达预算不自动无限续跑。

来源覆盖检查对照全部子块实际页面，保留原文范围断点。跨批冲突和重复从整个子块固定快照选择有限相关候选，不限制在同一十页批次。连续子块更新同页时保留双方前后快照，并检查先前贡献的丢失或失真；旧报告与事项随版本变化标为历史，不改写旧正文快照。批次有效事项幂等发布，保留人工状态。

导入过程采用来源父行与子块行，未分块及历史整文记录保持单行。来源计数、共享路径及共享事项去重；搜索保留父子上下文，轮询不覆盖用户折叠选择。子块展示批次成员、完成数、失败目标、累计耗时及快照。来源归档由父记录控制，回读全部子块和当前队列后执行，不改写审阅结果。

## 关键实现位置

| 模块 | 职责 |
|---|---|
| `src/lib/ingest-document.ts` | 固定来源、子块计划、预留身份与分析断点 |
| `src/lib/ingest-pipeline.ts` | 共享串行名额、内部租约与暂停 |
| `src/lib/ingest.ts` | 逐块生成、可靠写入、审阅交接与交互入口 |
| `src/lib/ingest-review-batches.ts` | 十页计划、语料身份、目标级恢复与失败摘要 |
| `src/lib/ingest-review.ts` | 批次与公共检查、材料范围、预算和事项发布 |
| `src-tauri/src/commands/search/evidence.rs` | 通道候选断点、版本核实、原 RRF 融合及目标统计 |
| `src/components/sources/import-process-document-row.tsx` | 来源父行与折叠状态 |
| `src/components/sources/import-process-run-row.tsx` | 子块状态、批次详情与页面快照 |
| `src/lib/llm-client.ts` | 请求结束时释放超时器和取消监听，避免连续审阅积累资源 |

## 验证结果

1. `npm run build`：类型检查与前端生产构建通过。构建仍提示既有的资源分包体积和静态／动态导入警告。
2. 34 个相关 Vitest 文件、631 个用例通过；没有运行整个仓库的所有测试。
3. Rust 检索相关测试：12 个通过，1 个真实传输评估入口默认忽略；真实服务评估另行显式调用该入口。
4. 真实服务评估：使用本地 Ollama 的 `qwen3.5:4b`、实际 Rust 关键词／索引检索、临时文件及 11 张合成短页。分成 10＋1，两批和所有公共检查均完成，未发现待办。最近一次耗时与调用数如下。

- 总耗时：28.991 秒；模型请求 13 次，失败 0 次。
- 第 1 批：10 页，检索 42 毫秒，批次状态 `complete`。
- 第 2 批：1 页，检索 40 毫秒，批次状态 `complete`。

详细结果：[真实批次审阅评估 JSON](evaluations/chunk-batch-review-2026-10-29.json)。评估同时触发并修复了连续调用累积取消监听的问题；修复后复测没有再出现该警告。另有 16 次连续成功、网络失败、HTTP 失败三组测试，验证每次请求结束后均无残留监听与超时器。

回归覆盖：17 页为 10＋7；两个子块分别生成 23、12 页并形成 3、2 批；普通分析和块内分析先后截断；重复主体任务隔离；父计划中断恢复；共享页面快照及历史状态；首批部分完成后继续下一批；重试只请求原批未完成目标；语料变化使旧无命中断点失效；跨第一批和第三批的重复检查；交互补写恢复；取消、项目切换、归档、父子计数及手动折叠保留。

## 效果边界

真实评估使用合成短文与关键词／索引通道，不能据此保证长文、向量服务或任意资料在 60 秒内完成。模型检查也不能保证穷尽全部冲突或重复关系，保存的检查范围是结论边界。容量不足和服务失败保留为未完成，不能算作正常无问题。

语料断点身份核对当前 Wiki 正文指纹、有效通道、Embedding 配置，以及启用向量时的索引 manifest。此核对在审阅执行开始时进行，会产生文件扫描成本；60 秒仅约束每批检索，不代表整段审阅的总耗时。
