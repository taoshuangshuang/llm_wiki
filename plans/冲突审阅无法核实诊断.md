# 冲突审阅反复无法核实：诊断与修复

日期：2026-10-28。

## 结论

`动态分配.md` 的页面写入已完成。阻塞发生在后台冲突复核：初筛取得完整材料，复核却只收到摘出的引文，没有表头、章节、材料身份和问题描述。真实模型因此把表格内的版本取值当成主张的适用版本，无法确认比较对象。

使用同一模型、同一系统提示词和相同引文做对照，仅增加实际消费的材料正文后，响应从 `incomplete` 变成完整判定。这个结果支持上下文丢失是本次故障的主要原因；具体内容是否确实矛盾仍由审阅事项交人工确认，不修改页面事实。

原始引文匹配失败是此前的另一处问题：第一次模型改写了引文，重试后又把其他材料中的原文标到了错误编号。严格逐字校验应继续保留。

## 本次修改

- 冲突复核携带候选描述、逐字证据及其对应消费材料的完整可用正文，保留路径、版本、快照位置和行号。不额外读取链接目标，不截断材料后声称已完整复核。
- 提示词要求先识别比较对象，区分表格中的版本枚举值与主张适用版本。
- 区分语义上无法判断与输出协议错误。无法判断时保留具体原因和缺失条件；JSON 或字段错误只重试复核，不重新生成初筛候选。
- 已有知识冲突必须同时引用本轮页面和实际检索到的已有知识，防止混入本轮内部候选。
- 规则版本升为 7；显式重查时旧规则报告留作历史，重新检查实际消费版本。

## 验证

1. 新增场景化集成测试先出现 3 个预期失败，分别覆盖上下文不足的正反判定与无法判断原因丢失。
2. 修改后，相关 7 个文件共 106 个测试通过，包括后台审阅、队列、过程日志、检索材料、归档及导入视图。
3. 真实模型复核用例 4 个通过：本次原始候选、同范围事实矛盾、版本差异、条件差异。
4. 真实任务快照在临时项目中走完整 `runIngestReview` 入口，全部步骤完成，两个页面正文与写入快照相同。
5. TypeScript 类型检查通过。
6. Vite 生产构建通过。当前终端 Node 20.17.0 低于 Vite 声明的最低版本，构建有版本提示；本机已存在 Node 24.22.1，测试版启动脚本会优先选择兼容运行时。本次未修改运行时或依赖。

真实模型仍使用当时配置的 `GLM-5.3-Flash`。检索在完整快照回放中重放原任务已持久化的正文证据，避免检索漂移干扰本次问题验证；该结果不等于重新验证当前全库检索质量。
