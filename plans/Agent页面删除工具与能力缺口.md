# Agent 页面管理工具与能力约定

## 已补齐的删除能力

此前审阅 Agent 能通过 `wiki.write_page` 合并页面，却没有专用删除入口，因此合并完成后重复文件仍可能保留。

现在提供三个入口，共用 `agent/wiki_delete.rs` 中的生命周期：

| 入口 | 调用方式 |
| --- | --- |
| 应用内 Agent | `wiki.delete_page`，参数 `path` |
| 本地 HTTP API | `POST /api/v1/projects/{id}/pages/delete`，请求体 `{"path":"wiki/concepts/old.md"}` |
| MCP | `llm_wiki_delete_page`，参数 `path`、可选 `project_id` |

知识树、Lint 以及来源删除后移除派生页面的完整清理入口，也通过 Tauri 调用这一实现。尚未落库页面的轻量回收、外部文件已被删除后的补偿清理保留各自原有入口。

行为约定：

- 删除前读取精确目标，核对需保留的内容已合并。审阅材料和来源正文不构成删除授权。
- 仅处理项目内 Wiki Markdown 页面，不支持目录、通配符、路径穿越或符号链接。
- 同步清理目录列表、正文 wikilink、frontmatter `related` 和受影响页面的旧向量。存活页的新向量由正文监听与索引核对流程恢复；后台 Agent/API 的删除成功不代表重新嵌入已完成。
- 路径链接按完整路径识别；存在存活同名页面时保留有歧义的裸名称或标题引用，不误删另一个 Schema 的链接。
- 预检所有受影响页面的保护规则；重要档案生成审批草稿，在人工审核前不改变原文。审批删除目标时仍走完整生命周期；其他受保护的引用页仍需各自审核。
- 扫描、保护预检失败时不修改页面；提交失败时尝试回滚本批文件。文件已经变更但索引或媒体回收失败时，通过 `warnings` 返回具体情况。
- 只对来源摘要回收无人引用的配图；其他页面和原始来源文件不会随之删除。
- 审阅项仍由用户确认解决。删除活动记录标为 `deleted`，不提供会破坏整批引用一致性的单文件撤销。已有版本历史开关继续生效。

结果字段为 `deletedPaths`、`rewrittenPaths`、`rewrittenFiles`、`warnings` 和 `verified`。`verified` 表示文件提交完成，调用方仍须展示 `warnings`。

应用后端需运行包含本次修改的构建；现有 MCP 客户端需重新连接以刷新工具列表。

## 补齐后的页面管理能力

页面列表、来源精确读取、页面移动或重命名均已实现。应用内 Agent 与 HTTP/MCP 共用后端行为。已有 `graph.search` 继续负责关系与反向引用，`user.ask` 负责交互选择；本次没有增加自动关闭审阅项的工具。

| 能力 | 应用内 Agent | HTTP | MCP |
| --- | --- | --- | --- |
| 页面列表 | `wiki.list_pages` | `GET /api/v1/projects/{id}/pages` | `llm_wiki_list_pages` |
| 来源精确读取 | `source.read_file` | `POST /api/v1/projects/{id}/sources/read` | `llm_wiki_read_source` |
| 移动或重命名 | `wiki.move_page` | `POST /api/v1/projects/{id}/pages/move` | `llm_wiki_move_page` |

### 页面列表

- 输入 `prefix`、`offset`、`limit`、可选 `snapshot`。默认前缀 `wiki/`，可按文件名前缀寻找全部 `-2/-3` 副本。
- 返回 `pages`（精确路径和字节数）、`total`、`nextOffset`、`truncated` 和 `snapshot`。页大小还受返回字符预算约束，必须以 `nextOffset` 判断后续位置。
- 续页携带相同 `snapshot`；匹配文件的路径或元数据变化时明确报错，要求重新枚举。扫描失败、存在符号链接或超过 20000 个扫描条目时，不把部分结果当完整列表。
- 隐藏目录和媒体目录不属于知识页面列表。列出的文件并不表示正文已经读取。

### 来源读取

- 输入精确 `raw/sources/` 路径，可指定从 1 开始的 `startLine`、`endLine`、`startColumn`，以及 `maxChars`、`revision`。
- 保留原始空白和换行，返回总行数、实际读取范围、正文版本及接续行列。长行可按字符接续，不依赖搜索片段或截断预览拼凑原文。
- 普通文本读取原文件；PDF、Office、EPUB 等读取应用已生成且未过期的提取正文。未提取或已过期时明确失败，不触发解析、不引用旧缓存。原文件与提取正文均有 16 MiB 读取预算，单次返回最多 12000 个字符。
- `truncated` 表示请求的行区间尚有未返回字符；显式指定部分行区间时，是否还有其他行应结合 `totalLines` 判断。
- 普通问答和“忠实来源”模式均可使用。来源、提取缓存及其祖先路径都不能穿透符号链接。

### 页面移动

- 输入源 `path`、目标 `toPath`，建议携带 `wiki.read_page` 或公开文件读取返回的 `expectedRevision`。源页变化、目标存在、源目标相同或路径非法时保持原状。
- 同一文件提交锁内更新 Wiki 链接、目录条目、frontmatter `related` 和普通 Markdown 链接。保留别名及锚点，跳过代码围栏和行内代码；跨目录时重算源页内的图片、文档及引用式 Markdown 链接相对路径。
- 同名页面的歧义裸名保留；完整路径引用只迁移匹配的源页。标题、来源字段和原始来源文件不随页面重命名而改写。
- 使用目标创建独占的硬链接语义防止覆盖并发新文件；文件系统不支持时失败并保留源页。引用页提交失败会恢复本批文件，回滚失败也会明确报告。
- 重要源页的移动会创建绑定源正文和目标路径的审批草稿。审批界面显示“移动至目标路径”及保留的原文；批准后迁移引用并继承重要标记，其他受保护的引用页仍需单独审核。
- 旧向量身份及引用页的旧向量会清理。有可用嵌入配置时重建受影响知识页；目录、日志和概览等聚合页不嵌入。未配置或重建失败时返回 `indexingPendingPaths`，清理或重建错误另列 `warnings`。
- 版本历史开关继续生效：记录移动前后版本，已有旧路径历史保留。审阅事项不会自动关闭。

本轮没有对真实知识库执行移动、读取任务或清理，验证使用临时项目、临时模型服务和真实 LanceDB。
