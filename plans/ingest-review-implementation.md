# 文件入库与后台审阅实施及验收记录

> 2026-10-29 更新：合并、四项检查及一轮修复相关条款以 [简化设计](入库合并与审阅流程简化设计-20261029.md) 和 [实施记录](入库合并与审阅流程简化实施记录-20261029.md) 为准；下文保留原方案供追溯。

日期：2026-10-25。对应需求：[改造方案](ingest-review-refactor.md)。本记录描述本地工作区实现及验证，不表示已安装新的桌面发行包。

## 1. 已落地行为

文件生成与写入结束后即释放入库执行名额。统一审阅由应用级独立队列执行，切换页签不会停止任务。重启恢复持久请求；切换项目暂停旧请求；取消与重试使用执行身份隔离晚到响应，不等待忽略取消的网络请求。

自动上传、来源监控、交互式入库、会话知识保存使用共同写入及审阅链路。会话保存先保留原始材料再入队；通用文件编辑和 HTTP 页面写入仍保留原有明确编辑语义，不因底层写文件而触发入库审阅。

| 领域 | 实现及可观察结果 |
|---|---|
| 可靠记录 | `.llm-wiki/ingest-runs/<runId>/source.json` 固定来源正文及 SHA-256；`manifest.json` 保存尝试次数、工作单元到最终路径的映射、提交意图、事件、首次覆盖前快照及最终正文 |
| 提交与恢复 | 先保存意图，再由 Rust 比较当前正文并原子替换。写后登记失败时，恢复只核实和补登记；遇到无法核实的当前版本时保留文件并要求恢复 |
| 并发保护 | 应用内原生写入共享提交锁；模型和网络等待不持锁。提交前只校验已消费文件及目标路径的快照，不扫描新增候选或再次调用模型；期间新增页面的疑似重复交后台审阅。来源原始字节用 MD5 检测变化，正文证据用 SHA-256。MD5 用于变化检测，不作为安全签名 |
| 合并降级 | 首次选择目标不唯一时写入独立路径，固定候选全文并随合并事项交后台审阅；候选后续变化时保留为历史证据。合并协议或质量不通过时采用完整生成稿并保存处理事件。若目标包含本轮先前片段，当前片段另存，保留已经写入的贡献 |
| 部分写入 | 完整 FILE 块保留，截断与失败单元留待补写；部分结果不进入完整成功缓存。日志和索引不能单独算作有效知识页 |
| 统一审阅 | 一份报告维护合并、格式、来源覆盖、局部冲突及全库相关知识检查；全库内部按冲突、重复、两类缺页、研究建议分项检查并保存检查点 |
| 检查与取消 | 可单独重试未完成检查；规则变化会使旧检查点失效；取消保留已经获得的有效事项。写入和审阅错误分别保存，重试审阅不会抹掉部分写入原因。重新审阅已完成任务时明确开启新报告，原报告保留 |
| 证据与时效 | 事项保存逐字正文、路径、行号、版本及来源快照。冲突增加对象、版本、适用条件复核。发布前核对消费版本，失效结果标记为历史；复核当前页不改写原入库快照 |
| 事项与人工状态 | 七类按合并、冲突、内容、格式、缺页、重复、建议排序。v2 身份基于问题及证据，标题不参与；旧 ID 保留别名。原生增量提交保留其他写入者的事项及较新的人工操作。清理已处理事项仅隐藏历史，防止重新加载后复活 |
| 生成缓存 | 成功缓存只绑定来源与生成规则。再次命中时仍可复查原写入记录；只修改审阅规则不重新生成页面 |
| 界面 | 主导航“资料”后新增“导入过程”。写入与审阅分别显示状态，提供补写、取消、审阅重试、事项跳转及前后快照；原文件同步和队列批量操作迁入该页活动区域 |
| 兼容 | API/MCP 保留原主类型和旧 ID 引用，增加子类、证据、处理结果与历史信息；审阅会话携带同一份版本化证据。“已审阅”仅记录人工确认 |

关键入口分别是 `src/lib/ingest-run.ts`、`ingest-review.ts`、`ingest-review-queue.ts` 和 `src-tauri/src/commands/search/evidence.rs`；原 acceptance 的结构与来源覆盖能力仅作为统一审阅内部检查复用，生产入库不再同步调用两套审阅发布流程。

## 2. 检索和执行参数

入库、审阅、桌面搜索、HTTP 搜索及 Agent 的 Wiki／来源／图搜索共用 Rust 证据核心。显式读取页面复用同一引用解析和版本协议；它属于明确读取材料，不是悄悄开启召回。

| 参数 | 当前值与含义 |
|---|---|
| 默认通道 | title、vector、keyword、indexPage 启用，graph 关闭；向量通道还要求 Embedding 配置启用。title 仅处理调用方明确提供的页面标题，入库和后台审阅已接入；普通问答、搜索和来源语料不将查询正文猜成页面标题 |
| 配置来源 | 应用数据目录 `retrieval-defaults.json` 保存全局默认；项目 `.llm-wiki/retrieval.json` 仅保存覆盖项。调用方只能进一步收窄有效通道 |
| 基本召回 | 每个目标：标题独立最多 3 个页面，向量最多 5 个片段，词法最多 5 个页面，索引最多 5 个目标页面。标题使用规范化字符二元组的 Dice 相似度，阈值 0.45；保留重复计数，避免堆叠关键词的长标题主导候选 |
| 融合 | 真实页面身份上的 RRF，k=60；同一页面在同一通道只投一票；独立正文片段仍可保留 |
| 最终证据 | 每目标最多 3 份标题候选完整正文，加最多 5 条其他候选片段；按页面身份取并集，同一标题候选不再重复展开为普通片段。标题候选保留独立名额，仍受正文与时间预算约束；全文不能装入预算时明确标记检查不完整。多个目标分别预算，可共享正文 |
| 图扩展 | 最多 5 个种子、一跳、20 个邻居，相关候选参与融合；不为无关邻居预留最终名额 |
| 单次检索预算 | 默认 40,000 正文字符、320 候选、32 个查询、20 秒；硬上限分别为 300,000、960、64、60 秒。查询最多 16,000 字符 |
| 读取与派生缓存 | Wiki 单文件读取上限 8 MB，累计正文读取上限 1,600 万字符；派生页缓存上限 64 MB。超过预算明确返回部分完成，不声称正常无命中 |
| 来源语料 | 使用启用的关键词通道；Office/PDF 等只读未过期的提取缓存。搜索不触发解析，隐藏目录中的缓存文件不作为独立来源 |
| 模型预算 | 每次审阅执行最多 16 个模型请求，协议最多重试一次；重试保留累计统计。内容校验、冲突初筛/复核和全库检查均按各自完整 system、user JSON 计算剩余输出额度，不再固定取 15% 或限制为 8K。现有上下文配置仍按字符计量：扣除完整输入和 1,024 字符安全余量后，每 4 字符估算一个输出 token；这不是精确分词计数。剩余不足 1,024 tokens 时明确未完成，不截掉材料、不强行分配最低额度。模型服务自身的单次输出限制仍适用 |

智谱官方 OpenAI 兼容接口的 `GLM-5.3` 与 `GLM-5.3-Flash` 均按已核对的推理协议适配：原审阅 `off` 请求映射为 `low`，明确发送 `thinking.type=enabled` 和 `reasoning_effort=low`，不落到默认 `max`。未知网关和 Anthropic 兼容接口不按模型名称套用私有参数。历史失败不会自动重跑，仍由用户手动重试审阅。

检索返回 `completed / partial / disabled / failed`、各目标状态、通道实际状态、查询、正文范围、原始方向引用及预算原因。过期向量片段无法在当前正文定位时不返回该片段。引用边不等于目标正文，也不等于观点支持关系。

标题相近只用于发现候选：入库仍读取完整正文，按原有同主题核对结果决定复用、独立建页或交审阅；后台审阅依据实际正文判断重复，不由标题分数直接生成重复事项。标题通道支持全局默认与项目覆盖，日志记录独立标题查询、通道候选及全文展开结果。标题参与检索断点身份，算法版本变更会使旧审阅检索缓存失效；不会自动重跑历史导入或修改已存在的知识页，也不要求重建向量索引。

## 3. 旧提示词与数据

新协议文件为 `prompts/07-01-统一后台审阅.md`，声明 `contract: review-v2`。默认页面生成仅输出 FILE；旧 REVIEW 块解析保留兼容，但不作为新的正式审阅结论发布。

已有自定义模板不会被覆盖。设置中的“后台审阅提示词迁移”可以查看旧模板、编辑新规则、备份并保存；保存前核对版本。自定义业务约束无法安全自动搬移、占位符未移除或新协议不完整时，保留原文件并将对应检查标记未完成。模板已准备好后可在导入过程只重新审阅。

原 acceptance 报告仍可用于恢复历史事项和人工状态。新事项不交给按文件名猜测“问题已解决”的旧巡检。旧问题说明不能充当已验证的知识事实。

## 4. 自动化验证

已验证的行为包含：真实文件的写前、写后及登记失败恢复；未知版本拒绝重放；同轮多片段保护；模型等待期间编辑与并发写入；部分写入补写；关闭检索不被重开；来源新旧字节检测；后台取消及项目切换的晚到响应隔离；只重试未完成检查；取消保留已获得事项；两类缺页、研究建议、重复的证据协议；人工状态及旧 ID；界面状态、操作和覆盖快照；MCP 证据字段。

检索测试实际建立临时 LanceDB，验证旧向量证据不被换上当前版本、同页独立片段保留，以及通道排名不重复投票。来源检索测试使用真实临时 PDF 提取缓存，检查原始路径和隐藏文件边界。

验证命令按受影响模块选择，不用构建替代行为测试。前端相关回归为 48 个文件、757 项；原生关键分组包括 Agent 202 项、共享搜索 31 项、审阅/API 19 项、比较提交 1 项、重要档案保护 14 项、文件历史 11 项；MCP 25 项。原生测试分组存在少量交叉，不相加冒充独立覆盖总数。另一个被忽略的原生测试仅供真实模型评估的 Node→Rust 传输，默认不调用模型。

前端 `npm run build` 包含 TypeScript 检查并成功构建。现有打包体积、混合静态/动态导入和原生工具链警告没有当作测试通过的证据。

扩大原生过滤条件到 `file_` 时，已有 `file_sync::tests::queue_lock_recovers_after_poison` 故意触发的 panic 在当前 macOS 调试测试二进制中引发 `libunwind: invalid compact unwind encoding`，进程 SIGABRT。因此没有将这次扩大范围的执行记为通过；受影响的文件历史、重要档案保护和比较提交模块已分别执行通过。没有为本需求改动该锁中毒测试或编译工具链。

## 5. 真实模型结果与边界

评估模型为本机 Ollama 的 `qwen3.5:4b`，通过公开 `runIngestReview` 入口执行，使用真实临时文件和实际 Rust 检索核心；仅将 Tauri IPC 替换为测试传输。测试不把模型命中率当作程序协议断言，效果单独记录在 [原始结果](evaluations/ingest-review-model-evaluation.json)。

| 自定义事实场景 | 结果 |
|---|---|
| 相同版本、相同条件下真正数值冲突 | 检出冲突，保存双方证据及适用范围复核 |
| 对象版本不同 | 未误报冲突 |
| 适用模式不同 | 未误报冲突 |
| 来源中关键细节未写入 | 检出内容遗漏 |
| 事实已嵌入现有章节，无独立维护需要 | 未报缺页；同时识别本次生成页与已有章节存在重复 |
| 明确尚未完成的对照实验 | 检出研究建议 |
| 不同标题、核心正文相同 | 检出疑似重复 |
| 材料提出需要独立维护页面 | 未提出缺页建议，作为漏报保留 |

按上述人工参考预期，7/8 个场景符合预期；5 个正向类型样例中命中 4 个，3 个反向样例没有出现指定的误报。它不是生产总体准确率，独立成页本身也需要人工判断。共 52 个模型请求，累计输入约 13.2 万字符，8 个场景累计约 67.5 秒；字符数不是供应商计费 token 数。

初轮实测曾把版本和条件差异误报为冲突；已经增加独立适用范围复核，并以确定性公开入口用例回归。将冲突、重复、缺页和研究建议拆分后，研究与重复正例的漏检得到改善，没有为样例添加专用关键词或改变统一召回权重。[中间评估记录](evaluations/ingest-review-model-evaluation-before-scope-input-fix.json) 仅用于保留误差证据。

本次完成的是可恢复、有证据且状态真实的执行链路。检索有界，模型仍可能漏报或误报；上下文不足、通道关闭、证据过期和执行失败会明确标记，人工审阅仍是最终决定。
