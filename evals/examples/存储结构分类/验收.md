# 验收：缓存条目存储结构分类

本文件只提供给评分者，不作为入库来源，也不随任务提供给执行者。

## 测试目的

验证主要介绍表结构的内容能归入 `data-model`，同时保留 DDL、字段语义及约束。该样例从真实误分类问题抽象而来，输入为合成材料；尚未运行，不能据此声称新版提示词有效。

## 成功标准

本示例以下六项均为关键项。输入以 `输入/缓存条目表说明.md` 为准。

1. 存在以 `cache_entry` 表及字段结构为主要内容的独立知识页面；仅生成来源摘要不算通过。
2. 上述内容页的 frontmatter `type` 为 `data-model`，FILE 路径位于 `wiki/data-models/`。
3. 来源摘要保留输入来源中完整的 CREATE TABLE 语句，允许换行和缩进变化；表名、四个字段名、类型、长度、可空性及主键与输入一致。
4. 对表结构的整理保留四个字段的含义，尤其是 `expires_at` 为空表示未设置过期时间；允许使用等价表述。
5. 生成的相关页面没有将来源未描述的淘汰算法、同步机制或接入步骤作为该表的既定事实。
6. 表结构内容页及来源摘要的 `sources` 均包含 `缓存条目表说明.md`。

## 允许变化

- 不固定页面标题、文件名、章节顺序和文字表述。
- 不要求固定的总页面数；按相关内容页逐项验收。
- 理解表结构所必需的字段约束可以随数据模型页保留，不要求单独创建约束页。

## 检查方法

| 标准 | 检查对象与方法 |
| --- | --- |
| 1 | 根据正文识别承载目标表结构的内容页；需要人工或模型辅助判断，不能只匹配标题。 |
| 2 | 对标准 1 中识别出的页面解析 frontmatter 并检查相对目录；程序可判定。 |
| 3 | 比较来源摘要代码块与输入 DDL，忽略换行和缩进；程序可判定。 |
| 4 | 对照输入字段表与相关正文，核对字段含义；先人工复核，后续再决定是否引入模型评分。 |
| 5 | 对照原始输入检查事实归属，记录疑似新增事实及其位置；需要语义复核。 |
| 6 | 解析相关页面 frontmatter 的 `sources` 数组；程序可判定。 |

每项结论记录通过、失败或待复核，并附文件位置及证据。待复核项不能计为通过。保留输入、模型请求与响应及最终页面，以便复查。
