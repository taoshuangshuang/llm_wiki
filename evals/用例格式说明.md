# Skill 回归验证格式

当前已实现为通用 skill：`/Users/taoshuang/.codex/skills/skill-validator`。采用已确认的回归测试范围：修改后运行全部已有 case，不测试自动触发、不运行基线、不保留旧版产物。

## 目录

```text
目标skill/
  SKILL.md
  scripts/、references/ 等原有资源
  evals/
    cases/
      case1/
        输入/
          用户对话.md
          背景、附件等实际材料
        输出/
          对话记录.md
          产物/                 # 有实际文件才创建
          错误日志.txt          # 非通过时按需保留
          执行记录.jsonl        # 非通过时按需保留
      case2/
        输入/
        输出/
    验证配置.json               # 可选，共用的超时与原有验收命令
    验证报告.html               # 唯一的最新汇总，内嵌结果数据
    版本变更记录.md             # 修改说明、内容指纹和历次简短摘要
```

用户只需准备输入，不强制创建场景 YAML 或重复的验收文件。案例里已有的验收定义可以作为后续特殊适配，但不默认注入执行者上下文。

## 新增用例与运行

```bash
python3 /Users/taoshuang/.codex/skills/skill-validator/scripts/validate_skill.py init --skill /实际/目标skill --case case1 --request '真实用户请求'
python3 /Users/taoshuang/.codex/skills/skill-validator/scripts/validate_skill.py run --skill /实际/目标skill --change-note '本次实际修改说明'
```

`init` 不覆盖已有 case。第一次创建时将附件放入对应输入目录；随后修改 skill 时直接 `run`，无需再次初始化。运行全部 case，各 case 只保存最新输出，一份报告汇总所有结果。已有非空手工输出不会被擅自删除；执行器仅覆盖它自己管理的目录。

单轮请求写在 `输入/用户对话.md`；真正多轮用 `输入/对话.json` 保存用户消息数组，每轮助手回复由实际执行产生。详见验证 skill 的运行约定。

## 公共逻辑与验收

新 CLI 进程、临时模型配置与工作区由验证器准备，续接只限本 case 创建的会话。每轮执行复制目标 skill 的当前版本，排除其验证材料和旧结果。

配置原有自验收命令时直接复用；未配置时，另一个无执行上下文的只读 Agent 依据 skill 原要求、用户输入、实际对话、临时执行证据与真实文件复核。成功不另存执行日志或自验收 JSON；关键项证据不足标记待复核，不能计为通过。

执行错误、产物不合格和待复核分开报告。必要产物缺失不能仅凭“已完成”判通过。只记录实际观测的用量，缺失指标为未知。

当前提供会话隔离、工作区副本和写入沙箱，不是宿主文件系统的强读取隔离。外部 MCP、插件、宿主绝对路径依赖和真实系统写入默认不适配，不能以绕过执行限制的方式强行验证。
