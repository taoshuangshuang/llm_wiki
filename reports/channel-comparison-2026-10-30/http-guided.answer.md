## imeta 是什么（仅依据本次会话实际检索/阅读的来源）

### 1. 定义与定位（现行资料，主题页）
**imeta 是 BIP 元数据体系中的查询组件，构件名为 iuap-ap-metaquery-starter，核心职责是「QuerySchema 到 SQL 的转换执行」。** 出处：wiki/topics/元数据（BIP平台）.md（现行主题页，updated 2026-10-17，本会话已完整阅读，"模块职责边界"表）。同表还给出与相邻框架的分工：**MDD 框架仅生成 SQL 返回框架，YPD 框架生成 SQL 并直接查询数据返回**——即 imeta 是两者共同依赖的查询执行底座。

### 2. 核心职责（查询 API 维度，现行资料）
imeta 对外的主要使用面是 **QuerySchema**：一套针对元数据的查询 API，风格遵循 GraphQL，屏蔽底层存储模型、完全面向元数据实体查询；**只读**（不支持增删改），返回 Map/List 嵌套结构、不支持直接返回 POJO；底层最终转换为 SQL，查询对象是元数据实体而非表，与更偏 SQL 风格、面向单实体不穿透的 YQL 相区别。出处：wiki/topics/QuerySchema（imeta 查询 API）.md（现行主题页，updated 2026-10-20，本会话已完整阅读）。

### 3. 上下游边界
- **上游调用方**：MDD 与 YPD 两个开发框架。wiki/concepts/MDD 与 YPD 调用 imeta 查询的入口与职责边界.md（本会话仅检索到页面导语，未读全文）说明二者各借用 imeta 哪段能力、各自接管哪段；该页自述"论断来自来源文档的断言性描述，未标注源码验证"。
- **下游**：SQL 执行与底层存储。QuerySchema 转 SQL 与实体获取的整体链路见 wiki/designs/imeta QuerySchema转SQL与实体获取流程.md，Spring 装配与查询核心生命周期见 wiki/designs/imeta Spring 装配与查询核心生命周期.md（均仅检索到片段，未完整阅读）。
- **与特征的边界**：imeta 只读取分配后的租户元数据并执行运行时操作，**"imeta 不负责决定某个租户应该有哪些特征"**，特征分配服务负责产生租户级属性。出处：wiki/constraints/imeta 特征属性处理使用边界约束.md（"职责边界"节，本会话检索片段）。
